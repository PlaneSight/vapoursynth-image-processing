# VapourSynth runtime

## Upstream and toolchain contract

Runtime adapters use `rust-av/vapoursynth-rs` commit
`ff6b542d3603c3075784303ffa1e44e283baa85c` (version 0.5.6) with default
features disabled. The dependency is pinned in both `Cargo.toml` and
`Cargo.lock`.

The upstream graph requires Rust 1.88 because `libloading` 0.9 declares that
MSRV. Pure VSIP crates continue to compile and run their tests on Rust 1.85.
Rust 1.97.1 is the pinned development and full-workspace release toolchain.

## ABI and ownership boundary

Each `adapters/*-vapoursynth` crate builds one `cdylib` and exports one
VapourSynth namespace. The only unsafe code admitted by those crates is the ABI
entry point generated by the upstream export macro. That macro catches unwinding
at the foreign boundary. VSIP adapter and algorithm code contains no handwritten
unsafe blocks.

VapourSynth owns source and destination frames. A frame callback borrows source
rows, obtains a copy-on-write destination, and holds all temporary memory in
exclusive scratch leases. A bounded pool retains idle buffers without holding a
mutex during kernel execution or sharing one buffer between parallel callbacks.
No frame borrow survives its callback.

## Formats and numeric policy

The common bridge supports planar u8, u16, and f32 samples. Half-precision f16
and 32-bit integer samples are rejected. Some filters impose narrower format or
plane-count contracts; for example, `masklab.Reconstruct` is u8-only and
`lens.Chromatic` requires planar RGB with equal plane extents.

Integer samples are converted to f32 without normalization, so numeric
parameters use the clip's native sample range. Results are rounded and clamped
to the format's declared bit depth. A non-finite f32 result is an error for an
integer destination rather than an implicit zero.

Analysis operations return clips so they compose with ordinary VapourSynth
graphs. Results that need signed or fractional components require planar RGB
f32 input and preserve that format. Their rendering contract is deliberate:

| Family | Analysis rendering |
| --- | --- |
| MaskLab / Segment | component labels, segmentation labels, or per-region degree |
| Defect | binary defect masks; repair operations consume explicit mask clips |
| Residual | signed residual fields, comparison fields, or spectrum power on f32 clips |
| FlowField | RGB f32 X displacement, Y displacement, and magnitude; confidence is replicated across planes; visualization emits RGB color |
| GrainLab | RGB f32 residual mean, residual variance, and temporal population variance |
| Phase | RGB f32 X/Y/magnitude translation fields, or mean/peak/active-energy fraction; magnification preserves source format |
| Register | estimated/warped frames, stack result, or stabilized frames |
| Deconvolve | restored frames or estimated full-frame PSF |

Component, graph, and statistical reports that do not map losslessly to frame
planes remain available through the pure Rust APIs. VapourSynth functions use
truthfully named raster or fixed-plane representations instead of discarding
components silently.

## Build and load

Build every adapter in release mode:

```text
cargo build --release --workspace
```

For MaskLab, the resulting library is named
`vs_masklab_vapoursynth.dll` on Windows,
`libvs_masklab_vapoursynth.so` on Linux, or
`libvs_masklab_vapoursynth.dylib` on macOS. Install it in a VapourSynth plugin
directory or load it explicitly:

```python
import vapoursynth as vs

core = vs.core
core.std.LoadPlugin(path="/absolute/path/to/vs_masklab_vapoursynth.dll")
source = core.std.BlankClip(width=640, height=360, format=vs.GRAY8)
distance = core.masklab.DistanceL1(source)
distance.set_output()
```

`tests/vapoursynth/catalog_smoke.vpy` loads all twelve libraries and verifies
that every catalogue function is visible. Set `VSIP_PLUGIN_DIR` to the absolute
`target/release` directory, then run:

```text
vspipe --info tests/vapoursynth/catalog_smoke.vpy -
```

`tests/vapoursynth/masklab_smoke.vpy` additionally executes a deterministic
frame-processing check. Set `VSIP_MASKLAB_PLUGIN` to the absolute release
library path, then run:

```text
vspipe --info tests/vapoursynth/masklab_smoke.vpy -
```

The ordinary CI graph builds the adapters on Windows, Linux, and macOS without
requiring a system VapourSynth installation. Runtime smoke tests require an
installed R4-compatible VapourSynth host and are therefore a separate gate.
